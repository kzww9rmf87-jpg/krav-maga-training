# UI KIT

Version 1.0

---

# Purpose

The UI Kit is the visual reference of the Combat Athlete System.

It defines how every screen is assembled.

It combines the Design System, Components and Motion into a coherent user interface.

Every new screen should be built from this document.

No screen should invent new layouts without a compelling reason.

---

# General Principles

Every screen answers one primary question.

Everything else is secondary.

The athlete should always know:

Where they are.

What they should do.

What happens next.

---

# Screen Structure

Every screen follows the same hierarchy.

Navigation

↓

Primary Information

↓

Primary Action

↓

Supporting Information

↓

Secondary Actions

↓

Background Information

Consistency reduces cognitive load.

---

# Home Screen

Purpose

"What should I do today?"

Components

• Today's Recommendation Card

• Readiness Card

• Next Session

• Weekly Progress

• Quick Actions

Only Today's Recommendation dominates the screen.

Everything else supports it.

---

# Training Screen

Purpose

Guide one exercise at a time.

Components

• Exercise Name

• Target Load

• Sets

• Repetitions

• Rest Timer

• Technique Notes

• Previous Performance

Nothing unrelated appears during training.

Training mode removes distractions.

---

# Rest Screen

Purpose

Recovery.

Components

• Large Countdown

• Next Exercise

• Previous Set Summary

• Skip Rest

The athlete should already know what comes next.

---

# Session Summary

Purpose

Understand today's work.

Components

• Duration

• Volume

• Total Load

• Session RPE

• Personal Records

• Coach Feedback

Keep the summary concise.

Avoid unnecessary statistics.

---

# Statistics Screen

Purpose

Support future decisions.

Components

• Performance Graphs

• Strength Progress

• Volume

• Recovery

• Readiness

• Training Consistency

Every graph must answer a coaching question.

---

# Exercise History

Purpose

Review previous performances.

Components

• Previous Loads

• Previous Sets

• Estimated 1RM

• Personal Records

Chronological order.

Latest performance first.

---

# Readiness Screen

Purpose

Evaluate today's capacity.

Components

• Readiness Score

• Sleep

• Fatigue

• Recovery

• Notes

The athlete immediately understands today's condition.

---

# Settings

Purpose

Configure the application.

Components

• Profile

• Units

• Notifications

• Voice Guidance

• Apple Health

• Export Data

Settings remain secondary.

---

# Cards

Every card communicates one idea.

Never multiple unrelated concepts.

Cards remain visually light.

Consistent padding.

Consistent spacing.

Consistent hierarchy.

---

# Buttons

One Primary Button.

Optional Secondary Button.

Text Buttons only when necessary.

Never multiple competing primary actions.

---

# Timers

Timers dominate only when timing matters.

Large typography.

Minimal surrounding elements.

Immediate readability.

---

# Graphs

Simple.

Minimal.

Actionable.

No decorative effects.

No unnecessary legends.

No excessive colors.

---

# Lists

Clean.

Simple.

Scannable.

The athlete should recognize patterns immediately.

---

# Empty States

Every empty state teaches the next step.

Never leave the athlete wondering what to do.

---

# Error States

Errors explain:

What happened.

Why.

How to recover.

Remain calm.

Remain concise.

---

# Success States

Success confirms.

It does not celebrate.

Subtle confirmation.

Immediate continuation.

---

# Responsive Design

The interface adapts naturally to:

Small iPhones.

Large iPhones.

iPads.

Landscape mode when appropriate.

Hierarchy never changes.

Only layout adapts.

---

# Future Components

New components should inherit:

Colors

Typography

Spacing

Motion

Component behavior

Never introduce visual exceptions.

---

# Final Principle

Every screen should feel as though it was designed by the same person.

Years apart.

Without needing to think about it.

The athlete should experience one coherent product.

Not a collection of screens.
