# DESIGN SYSTEM

Version 0.1

---

# Purpose

The CAS Design System defines how the Combat Athlete System should look, feel and behave.

It is not a collection of visual components.

It is a design philosophy.

Every interface decision must reinforce the mission of CAS:

Helping athletes become more capable while reducing cognitive effort.

The interface exists to support training.

Never to become the center of attention.

---

# Design Philosophy

The application should communicate three emotions.

Calm.

Confidence.

Competence.

Everything else is secondary.

The athlete should never feel overwhelmed.

Never feel judged.

Never feel distracted.

---

# Simplicity

Every screen should feel obvious.

Every action should feel natural.

Every interaction should disappear as quickly as possible.

Complexity belongs inside the engine.

Never inside the interface.

---

# Visual Identity

CAS avoids the visual language of traditional fitness applications.

No flames.

No lightning bolts.

No aggressive reds.

No exaggerated motivation.

The visual language is quiet.

Professional.

Timeless.

The application should feel closer to Apple Health than to a bodybuilding app.

---

# Color Philosophy

Color communicates meaning.

Never decoration.

Recommended palette:

Primary

Deep Blue

Trust.

Precision.

Stability.

Secondary

Soft Green

Recovery.

Progress.

Balance.

Neutral

White

Light Gray

Dark Gray

Black

Warning

Amber

Danger

Red

Only when necessary.

Large areas of saturated color should be avoided.

White space is preferred over decoration.

---

# Typography

Typography carries hierarchy.

Not decoration.

Large titles.

Short sentences.

Minimal text.

Readable at arm's length inside a gym.

Never use typography to create excitement.

Use typography to create clarity.

---

# Icons

Icons should describe actions.

Never decorate screens.

Every icon must answer the question:

Would removing this icon reduce understanding?

If not, remove it.

---

# Motion

Animation has only one purpose.

Helping understanding.

Transitions should explain changes.

Never impress.

Never entertain.

Motion should feel natural.

Fast.

Smooth.

Predictable.

---

# Components

Components must remain consistent throughout the application.

Buttons.

Cards.

Lists.

Timers.

Graphs.

Every component should have a single obvious purpose.

Avoid creating multiple visual styles for similar functions.

---

# Information Density

Show only what matters now.

Everything else waits.

The interface should reveal information progressively.

Not all at once.

---

# Home Screen

The Home Screen contains one primary card.

Today's Recommendation.

Everything else is secondary.

The athlete should know what to do within three seconds.

---

# Training Screen

During a session, only one exercise deserves attention.

Everything unrelated disappears.

Large timer.

Large weight.

Large repetition target.

Minimal interaction.

---

# Statistics

Statistics exist to support decisions.

Not curiosity.

Every graph must answer a practical question.

If a graph does not change future behavior, it should not exist.

---

# Accessibility

CAS is designed for real training environments.

Bright sunlight.

Dark gyms.

Sweaty hands.

Fatigue.

Stress.

The interface must remain usable under all conditions.

Large touch targets.

High contrast.

Readable typography.

Minimal gestures.

---

# Tone

The application speaks like an experienced coach.

Professional.

Calm.

Respectful.

Never sarcastic.

Never childish.

Never exaggerated.

The athlete is treated as a competent adult.

---

# Apple Principles

The CAS interface follows principles similar to Apple's Human Interface Guidelines.

Clarity.

Deference.

Depth.

The interface supports content.

It never competes with it.

---

# Timelessness

Design trends change.

Human physiology changes slowly.

The CAS Design System prioritizes timeless design over fashionable design.

An interface should still feel appropriate ten years after it was created.

---

# Final Principle

The athlete should remember the training session.

Not the interface.

If users talk about the design more than their progress, the Design System has failed.
