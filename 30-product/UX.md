# UX

Version 0.1

---

# Purpose

The purpose of the CAS user experience is to reduce cognitive effort.

The athlete should never have to think about the application.

The application should think for the athlete.

Every interaction must reduce uncertainty.

Every screen must answer a question.

Nothing else.

---

# UX Philosophy

CAS follows one simple rule.

One screen.

One decision.

One action.

If a screen contains multiple competing objectives, it should be redesigned.

---

# Opening the App

Opening CAS should never feel like opening software.

It should feel like asking a trusted coach.

The application immediately understands the current context and presents a single recommendation.

No dashboards.

No statistics.

No distractions.

---

# Home Screen

The Home screen answers three questions.

What should I do today?

Why today?

How long will it take?

Everything else is secondary.

---

# Training Screen

During training, the athlete should never need to search for information.

Only the current exercise is visible.

The next exercise remains hidden until needed.

Focus stays on execution.

Not planning.

---

# During Rest

Rest periods are intentionally quiet.

The interface should never encourage unnecessary interaction.

The athlete rests.

The application waits.

---

# Session Completion

At the end of a session, the application asks only the minimum information required to improve future decisions.

Examples

Energy before training.

Difficulty.

Pain.

Comments.

Nothing more.

The athlete leaves the application within seconds.

---

# Progressive Disclosure

CAS never shows everything.

Information appears only when it becomes useful.

Beginners see simplicity.

Advanced athletes can explore deeper explanations.

Complexity is earned.

Never imposed.

---

# Decision Transparency

Every recommendation can be explained.

The athlete may ask:

Why this exercise?

Why today?

Why this load?

The explanation should always be available.

But never forced.

---

# Visual Hierarchy

Every screen has one primary element.

One secondary element.

Everything else supports them.

The eye should never hesitate.

---

# Error Prevention

The application assumes that mistakes come from design.

Not from the user.

The interface prevents errors before they occur.

Examples

Impossible training combinations.

Unsafe progressions.

Missing recovery.

Pain warnings.

---

# Feedback

Feedback is calm.

Neutral.

Professional.

The application never celebrates meaningless actions.

Completing a workout is expected.

Real progress deserves recognition.

---

# Notifications

CAS sends as few notifications as possible.

Silence is the default.

Notifications exist only when they improve decision making.

Never to increase engagement.

---

# Accessibility

The interface must remain usable

when tired,

when sweating,

when outdoors,

when wearing gloves,

when training quickly.

Large touch targets.

Readable typography.

Minimal interaction.

---

# Emotional Design

CAS should create confidence.

Never pressure.

The athlete should feel

guided,

supported,

competent,

never judged.

---

# Final Principle

The best training session is the one where the athlete almost forgets the application exists.

CAS succeeds when attention remains on movement, not on the screen.
