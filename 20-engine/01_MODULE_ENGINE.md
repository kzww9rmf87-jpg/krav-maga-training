# MODULE ENGINE

Version 0.1

---

# Purpose

The Module Engine is the architectural core of the Combat Athlete System.

Its purpose is to transform physiological objectives, cycle priorities and athlete constraints into structured training sessions.

The Module Engine never starts from exercises.

It always starts from the desired adaptation.

Exercises are implementation methods.

Adaptations are the objective.

Every training session generated by CAS results from the selection and assembly of Capability Modules according to:

* physiological priorities;
* athlete state;
* recovery capacity;
* training history;
* available resources;
* session constraints;
* long-term development priorities.

The Module Engine defines what must be developed and which functional training blocks are required.

Exercise selection, loading parameters, substitutions, validation and decision tracing are governed by the dedicated engine rules built on top of this architecture.

---

# Core Philosophy

The Module Engine follows one immutable principle:

> Build adaptations, not workouts.

A workout is a temporary arrangement of training elements.

A capability is a long-term human performance quality.

An adaptation is the physiological change required to improve that capability.

The engine therefore optimizes useful adaptation rather than fatigue, complexity or exercise variety.

Fatigue may result from training.

Fatigue is never the objective of training.

---

# Core Concepts

## Adaptation Domain

An Adaptation Domain represents a fundamental physical quality that can be developed through physical preparation.

The current CAS Adaptation Domains are:

* Maximum Strength
* Power
* Functional Hypertrophy
* Conditioning
* Robustness
* Movement
* Recovery

Every Capability Module belongs to exactly one primary Adaptation Domain.

An Adaptation Domain is not a Capability Module.

A domain describes a physiological finality:

> What physical quality is the athlete being asked to develop?

It is not an operational block that the engine inserts directly into a session.

Several distinct Capability Modules may serve the same Adaptation Domain when they represent different training functions, mechanisms or positions within a session.

---

## Specific Skill

Specific Skill represents the technical and tactical practice of the athlete's target discipline.

Examples include:

* striking technique;
* grappling technique;
* defensive reactions;
* combinations;
* tactical decision-making;
* sport-specific timing;
* technical sparring;
* discipline-specific drills.

Specific Skill is not a directly trainable Adaptation Domain of the CAS physical preparation engine.

CAS does not replace the practice of the target discipline.

Specific Skill is treated as an external practice domain that influences physical preparation decisions.

The engine may use information about specific-skill practice to determine:

* accumulated fatigue;
* recovery requirements;
* movement demands;
* energy-system demands;
* injury exposure;
* weekly load;
* competition proximity;
* physical priorities.

An exercise associated with the target discipline may still be used inside a physical Capability Module when its primary purpose is physical rather than technical.

For example:

* explosive heavy-bag strikes may implement a Power module;
* repeated heavy-bag intervals may implement a Conditioning module;
* controlled footwork drills may implement a Movement module.

In such cases, the exercise does not create a Specific Skill module.

The selected Capability Module remains defined by its primary physiological objective.

> Physical preparation supports specific practice. It never replaces it.

---

## Capability

A Capability is a real action or performance outcome expressed as something a human can do.

Examples include:

* push;
* pull;
* carry;
* run;
* jump;
* strike;
* accelerate;
* decelerate;
* rotate;
* resist rotation;
* get up;
* maintain a grip;
* absorb force;
* transmit force;
* resist a perturbation;
* repeat high-intensity efforts.

Capabilities describe the functional reason behind physical preparation.

They answer:

> What must the athlete become able to do?

Capabilities are acknowledged doctrine within CAS but are not yet implemented as a distinct modeled layer in Version 0.1.

No dedicated `Capability` type or mandatory Capability field currently exists in the engine.

The concept is recorded here to ensure that Capability and Capability Module are never treated as synonyms.

---

## Capability Module

A Capability Module is the smallest reusable functional training unit assembled by the Module Engine.

It translates an Adaptation Domain into an operational training block.

It answers:

> What type of training block should be used to develop the required adaptation?

A Capability Module is not an Adaptation Domain.

The Adaptation Domain describes the physiological finality.

The Capability Module describes how that finality is organized within training.

A Capability Module is also not a Capability.

A Capability is an action the athlete must be able to perform.

A Capability Module is a reusable training block used to develop the physical qualities required by that action.

A module must have exactly one primary adaptation.

Never zero.

Never more than one.

A module may contain zero or several secondary adaptations when those relationships are supported by an identified scientific or doctrinal source.

Secondary adaptations:

* document relevant physiological effects;
* improve future analysis;
* may contribute to reporting;
* may help identify interactions between modules.

Secondary adaptations must never:

* replace the primary adaptation;
* justify module selection by themselves;
* override cycle priorities;
* override safety rules;
* weaken the distinction between primary and secondary objectives.

A Capability Module is independent from any single exercise.

Different exercises may implement the same module.

The same exercise may implement different modules when its execution parameters, intent, intensity, duration or loading structure change.

For example, a medicine-ball throw may implement Power.

A repeated medicine-ball circuit may implement Conditioning.

The exercise name alone does not define the module.

The intended adaptation and execution parameters define the module.

---

## Exercise

An Exercise is a concrete method used to implement a Capability Module.

Exercises are selected only after the engine has determined:

* the required Adaptation Domain;
* the required Capability Module;
* the purpose of the module within the session;
* the athlete's constraints;
* the appropriate training parameters.

Exercises are implementation details.

They must never determine the objective retroactively.

The engine does not choose an exercise because it is popular, difficult, entertaining or traditional.

It chooses an exercise because that exercise is an appropriate implementation of the selected module for the current athlete and context.

---

## Training Session

A Training Session is an ordered and validated assembly of selected Capability Modules.

A session is temporary.

The modules are reusable.

A session exists to execute one or more priorities defined by the athlete's current training context and Training Cycle.

Its objective is not to maximize:

* fatigue;
* discomfort;
* exercise count;
* calorie expenditure;
* novelty;
* complexity.

Its objective is to maximize useful adaptation while respecting:

* recovery capacity;
* technical quality;
* available time;
* equipment;
* injury constraints;
* current readiness;
* recent training exposure;
* upcoming specific practice.

A session is not required to contain every Capability Module.

Only modules justified by the session objective and athlete context should be selected.

---

## Training Cycle

A Training Cycle is an organized sequence of sessions designed to prioritize selected adaptations over time.

The Training Cycle establishes:

* primary development priorities;
* secondary maintenance priorities;
* expected training frequency;
* acceptable fatigue distribution;
* progression objectives;
* planned recovery;
* competition or performance deadlines.

Cycles define priorities over time.

Sessions execute those priorities.

Capability Modules provide the reusable training blocks required by the sessions.

Exercises implement the modules.

---

# Canonical Capability Module Catalog

The Module Engine assembles sessions from a fixed catalog of canonical Capability Modules.

It does not assemble sessions directly from Adaptation Domains.

It does not invent new module categories for individual sessions.

The Version 0.1 catalog is:

1. Preparation
2. Movement
3. Power
4. Strength
5. Functional Hypertrophy
6. Robustness
7. Grip
8. Core
9. Conditioning
10. Recovery

This catalog is stable business data.

Sessions are temporary assemblies of modules.

Modules are not generated dynamically from sessions.

The catalog may evolve when new operational needs are identified.

Any new module must satisfy all module-definition rules described in this document.

---

## Preparation Module

Primary Adaptation:

* Movement

Secondary Adaptations:

* None currently modeled

Purpose:

The Preparation module transitions the athlete from the pre-session state to a state suitable for the main work.

It prepares the athlete to express the required movements and intensities safely and efficiently.

It may include:

* progressive tissue temperature increase;
* general movement;
* specific movement rehearsal;
* low-intensity activation;
* gradual exposure to the session's primary patterns;
* progressive rehearsal of force or velocity demands.

Preparation exists as a separate module because it occupies a distinct operational position before the main training work.

Its purpose is not to create fatigue.

Its purpose is to improve readiness for the adaptations targeted later in the session.

Preparation must remain proportional to the session.

It must not consume resources required by the main modules.

---

## Movement Module

Primary Adaptation:

* Movement

Secondary Adaptations:

* None currently modeled

Purpose:

The Movement module develops usable movement quality.

It may target:

* active range of motion;
* motor control;
* coordination;
* positional control;
* movement efficiency;
* controlled transitions;
* movement options;
* technical execution of general physical patterns.

Movement training is not passive flexibility work by default.

Its purpose is to improve the athlete's ability to access and control useful positions during action.

---

## Power Module

Primary Adaptation:

* Power

Secondary Adaptations:

* None currently modeled

Purpose:

The Power module develops the ability to produce force rapidly.

It may target:

* rate of force development;
* explosive intent;
* acceleration;
* ballistic force production;
* rapid force transmission;
* high-velocity expression of strength.

Power quality depends on maximal intent and technical quality.

Power work must stop or be modified when fatigue causes a meaningful loss of:

* velocity;
* explosiveness;
* coordination;
* intent;
* technical execution.

Power is never trained effectively under significant neural fatigue.

---

## Strength Module

Primary Adaptation:

* Maximum Strength

Secondary Adaptations:

* Power
* Robustness

Purpose:

The Strength module develops the athlete's ability to produce high levels of force.

It may target:

* maximal force production;
* recruitment of high-threshold motor units;
* force expression in fundamental movement patterns;
* improved force potential for later power development;
* increased tolerance to high mechanical tension.

The Strength module may contribute secondarily to Power and Robustness where supported by the CAS physical model.

These secondary effects do not change the module's primary purpose.

The Strength module is selected primarily to develop Maximum Strength.

---

## Functional Hypertrophy Module

Primary Adaptation:

* Functional Hypertrophy

Secondary Adaptations:

* None currently modeled

Purpose:

The Functional Hypertrophy module develops useful muscle mass that supports the athlete's performance requirements.

Its objective is not maximal bodybuilding-style muscular development without regard to function.

Functional Hypertrophy must remain compatible with:

* movement quality;
* relative strength;
* speed;
* recovery;
* sport-specific body-mass requirements;
* joint tolerance;
* long-term athletic development.

The module may use moderate or high local muscular volume when justified, but unnecessary fatigue and non-functional volume must be avoided.

---

## Robustness Module

Primary Adaptation:

* Robustness

Secondary Adaptations:

* None currently modeled

Purpose:

The Robustness module develops tolerance to repeated mechanical stress and reduces vulnerability to foreseeable training demands.

It may target:

* connective-tissue tolerance;
* joint control;
* local structural capacity;
* deceleration tolerance;
* repeated loading tolerance;
* resilience in exposed positions;
* low-level stabilizing capacity;
* tolerance to sport-relevant mechanical demands.

Robustness is not the absence of injury.

It is the gradual development of physical capacity to tolerate expected stress.

Robustness work must remain progressive and proportionate.

Pain provocation is not proof of effectiveness.

---

## Grip Module

Primary Adaptation:

* Robustness

Secondary Adaptations:

* None currently modeled

Purpose:

The Grip module develops the ability to create, maintain and repeat force through the hands, fingers, wrists and forearms.

It exists separately from the broader Robustness module because grip has:

* distinct exercise families;
* distinct fatigue characteristics;
* distinct recovery constraints;
* direct relevance to multiple combat sports;
* specific progression and testing requirements.

The Grip module may target:

* crushing grip;
* support grip;
* pinch grip;
* open-hand strength;
* wrist control;
* grip endurance;
* repeated gripping ability.

Grip remains classified under Robustness because its primary purpose within the current architecture is to improve tolerance and force maintenance in structures exposed to repeated gripping demands.

---

## Core Module

Primary Adaptation:

* Movement

Secondary Adaptations:

* None currently modeled

Purpose:

The Core module develops the ability to organize the trunk during human movement.

It may target:

* force transmission;
* trunk control;
* postural organization;
* anti-extension;
* anti-rotation;
* anti-lateral flexion;
* controlled rotation;
* coordination between the upper and lower body;
* maintenance of effective positions under load or perturbation.

The Core module belongs primarily to Movement because its main objective is to organize posture, force transmission and trunk control during action.

Robustness may occur as a secondary physiological consequence, but it is not currently modeled as the module's primary selection objective.

The Core module is not defined by abdominal muscle fatigue.

It is defined by improved trunk function during movement.

---

## Conditioning Module

Primary Adaptation:

* Conditioning

Secondary Adaptations:

* None currently modeled

Purpose:

The Conditioning module develops the athlete's ability to produce, sustain and repeat work.

It may target:

* aerobic capacity;
* aerobic power;
* anaerobic capacity;
* repeated high-intensity effort;
* recovery between efforts;
* sport-relevant work-to-rest tolerance;
* general work capacity.

Conditioning must support the athlete's overall performance.

It must not unnecessarily compromise:

* strength development;
* power expression;
* technical practice;
* recovery;
* muscle-mass objectives.

Conditioning methods are selected according to the required energy-system adaptation, not according to how exhausting they feel.

---

## Recovery Module

Primary Adaptation:

* Recovery

Secondary Adaptations:

* None currently modeled

Purpose:

The Recovery module improves readiness for future training and supports tolerance of the overall training process.

It may include:

* low-intensity movement;
* controlled aerobic work;
* breathing-based downregulation;
* mobility at recovery intensity;
* circulation-promoting activity;
* low-load technical rehearsal;
* deliberate reduction of physiological arousal.

Recovery is not complete inactivity by definition.

It is the deliberate management of training stress to improve future adaptation.

A Recovery module must not create a recovery cost disproportionate to its purpose.

* Baseline Metrics
* Progression Rules

* Exit Criteria
* Outcome Metrics

* greater load;
* greater velocity;
* greater technical quality;
* greater range of motion;
* more repetitions;
* more total work;
* improved density;
* reduced effort cost;
* shorter recovery time;
* greater movement complexity;
* improved tolerance.

# Module Definition Rules

The following rules are absolute.

---

## Rule 1 — One Primary Adaptation

Every Capability Module must have exactly one primary adaptation.

Never zero.

Never two.

Secondary adaptations may be recorded, but they never share primary status.

---

## Rule 2 — Distinct Operational Function

Every Capability Module must represent a distinct and reusable training function.

A module must differ meaningfully from other modules through at least one of the following:

* operational purpose;
* physiological mechanism;
* training parameters;
* constraints;
* progression model;
* position within the session;
* recovery profile.

If a proposed module cannot be distinguished meaningfully from an existing module, it should not exist separately.

Modules do not need to create unique Adaptation Domains.

Several modules may serve the same domain when their operational functions are distinct.

---

## Rule 3 — Simplicity

A module must remain simple enough to be understood, selected and validated reliably.

Each module requires:

* one primary physiological objective;
* one clear operational purpose;
* one coherent progression model;
* at least one measurable outcome.

A module must not become a miscellaneous category for unrelated exercises.

---

## Rule 4 — Adaptation Before Completion

A module must never compete with its own objective.

If accumulated fatigue, pain, technical degradation or athlete state prevents the intended adaptation, the module must be:

* modified;
* reduced;
* substituted;
* postponed;
* removed.

Completing the planned work is never more important than preserving the intended training effect.

---

## Rule 5 — Reusability

Modules are reusable.

They are independent from specific sessions and Training Cycles.

The same module may appear:

* in different sessions;
* at different frequencies;
* with different exercises;
* with different parameters;
* in different Training Cycles;
* for different sports.

Its primary adaptation and operational purpose remain stable.

---

## Rule 6 — Exercise Independence

No Capability Module may be defined by one mandatory exercise.

An exercise may be strongly associated with a module, but the module must remain valid when that exercise is unavailable or inappropriate.

A valid module must support:

* alternatives;
* regressions;
* progressions;
* substitutions.

---

## Rule 7 — Evidence and Doctrine

Module claims must be supported by:

* CAS foundation documents;
* accepted physiological principles;
* identified scientific evidence;
* explicit system doctrine.

Unsupported secondary adaptations, mechanisms or benefits must not be added as assumed facts.

Uncertainty must be documented rather than hidden.

---

## Rule 8 — Measurability

Every module must contain at least one observable or measurable indicator of progression.

Examples include:

* force produced;
* load completed;
* movement velocity;
* repetition quality;
* total work;
* work-to-rest tolerance;
* range of motion;
* symptom response;
* technical consistency;
* recovery time.

A module without a measurable outcome cannot be evaluated reliably.

---

# Module Selection

The Module Engine selects modules before selecting exercises.

Module selection must be based on:

* primary session objective;
* Training Cycle priorities;
* athlete readiness;
* recent training exposure;
* accumulated fatigue;
* recovery capacity;
* pain and restrictions;
* available time;
* equipment context;
* upcoming specific practice;
* long-term development needs.

A module must not be selected only because:

* it was used in the previous version of the workout;
* the athlete enjoys its exercises;
* the exercise is popular;
* the session appears too short;
* more variety is desired;
* additional fatigue seems desirable.

Every selected module must have an explicit justification.

Every omitted high-priority module must also be explainable when relevant.

Detailed module-selection priorities are defined in the dedicated decision, conflict and scoring rules.

---

# Session Assembly

Training sessions are assembled according to physiological and practical priorities.

The default relative order is:

Preparation

↓

Movement

↓

Power

↓

Strength

↓

Functional Hypertrophy

↓

Robustness

↓

Grip

↓

Core

↓

Conditioning

↓

Recovery

This order applies only to modules selected for the session.

A session is not expected to contain every module.

For example, a session may contain only:

* Preparation;
* Power;
* Strength;
* Core;
* Recovery.

The selected modules retain their relative order unless a justified exception applies.

Module inclusion is determined by:

* session objective;
* Training Cycle priorities;
* athlete state;
* available time;
* fatigue budget;
* recovery capacity;
* sport schedule;
* practical constraints.

The default order reflects the principle that tasks requiring the greatest:

* technical precision;
* coordination;
* velocity;
* neural freshness;
* force expression

should generally occur before tasks that create substantial muscular or metabolic fatigue.

The order may change only when a scientific, physiological or practical justification exists.

Any change from the default order must be recorded in the Decision Trace.

---

# Session Assembly Principles

## Principle 1 — Priority Modules First

Modules serving the primary objective of the session must receive priority in:

* time;
* fatigue budget;
* exercise quality;
* athlete attention.

Secondary work must not compromise the primary work.

---

## Principle 2 — High-Skill and High-Velocity Work Before Fatigue

Movement requiring high coordination, maximal intent or high velocity should generally occur before significant fatigue.

This includes most Power work.

---

## Principle 3 — Fatigue-Producing Work Later

Modules that create substantial local muscular or metabolic fatigue should generally occur after high-priority neural and technical work.

---

## Principle 4 — Recovery May Be Integrated or Terminal

Recovery may appear:

* as a final module;
* as low-intensity work between demanding exposures;
* as the primary purpose of a dedicated session.

Its position depends on its operational purpose.

---

## Principle 5 — Minimum Effective Assembly

The engine should select the smallest combination of modules capable of producing the required adaptation.

Additional modules must not be added without justification.

A shorter coherent session is superior to a longer incoherent session.

---

# Fatigue Management

Fatigue is a limited resource.

It is not an objective.

Each module contributes to four independent fatigue dimensions:

* Neural Fatigue
* Muscular Fatigue
* Connective Tissue Stress
* Metabolic Fatigue

These dimensions must not be merged automatically into one universal fatigue value.

An athlete may be:

* neurally fresh but locally muscularly fatigued;
* metabolically recovered but connective tissues still stressed;
* generally energetic but unable to express power safely;
* muscularly recovered but technically degraded.

The engine must evaluate cumulative fatigue before and during session assembly.

It must consider fatigue produced by:

* recent CAS sessions;
* specific-skill practice;
* competition;
* occupational activity;
* sleep disruption;
* pain;
* illness;
* unusual life stress;
* previous session performance.

If the predicted recovery cost exceeds the athlete's available capacity, the session must be modified.

Possible modifications include:

* reducing volume;
* reducing intensity;
* reducing density;
* replacing an exercise;
* removing a secondary module;
* replacing a demanding module with Recovery or Movement;
* postponing the primary stressor;
* refusing to generate the requested session.

Adaptation always takes priority over completion.

---

# Recovery Capacity

Recovery capacity limits the total training dose that may be prescribed.

It is influenced by:

* sleep;
* nutrition;
* recent workload;
* training age;
* age;
* stress;
* illness;
* pain;
* competition schedule;
* specific-skill training;
* individual response history.

The engine must not assume that the athlete can recover simply because a session is theoretically valid in isolation.

A session is valid only when it is compatible with the athlete's broader training context.

---

# Progression Logic

Each Adaptation Domain follows a distinct progression logic.

The statements below define the general direction of progression.

Detailed progression rules, thresholds and algorithms are specified within individual module definitions and dedicated engine rules.

---

## Maximum Strength

Objective:

Increase force production while maintaining acceptable technical quality.

Possible progression indicators include:

* increased external load;
* increased repetitions at a given load;
* reduced perceived effort at a given load;
* improved bar or movement velocity;
* improved technical consistency;
* increased estimated maximal strength.

Load must not increase when technical quality or safety deteriorates beyond acceptable limits.

---

## Power

Objective:

Increase rapid force production while preserving maximal intent and movement quality.

Possible progression indicators include:

* increased movement velocity;
* increased jump or throw output;
* greater external load at preserved velocity;
* improved repeated explosive performance;
* reduced velocity loss;
* improved technical execution at maximal intent.

More fatigue is not progression.

A reduction in velocity or intent may require the set or module to stop.

---

## Functional Hypertrophy

Objective:

Increase useful muscle mass while preserving movement quality, relative performance and recovery.

Possible progression indicators include:

* increased productive training volume;
* increased load within the target repetition range;
* improved repetition quality;
* improved local work tolerance;
* measurable body-composition change;
* improved support of strength or robustness goals.

Volume must not increase when it produces disproportionate fatigue or interferes with higher-priority adaptations.

---

## Conditioning

Objective:

Increase the athlete's ability to produce, sustain and repeat required work.

Possible progression indicators include:

* increased sustainable output;
* increased total work;
* improved work-to-rest ratio;
* faster recovery between efforts;
* reduced physiological cost at a given output;
* improved repeated high-intensity performance;
* improved sport-relevant conditioning tests.

Conditioning progression must not compromise priority strength, power or technical adaptations.

---

## Movement

Objective:

Increase usable range of motion, motor control and movement efficiency.

Possible progression indicators include:

* increased active range;
* improved control;
* improved positional quality;
* reduced compensation;
* increased movement complexity;
* improved execution under light or moderate load;
* improved transfer to relevant physical actions.

Passive range without usable control is not sufficient evidence of progression.

---

## Robustness

Objective:

Increase tolerance to repeated and foreseeable mechanical stress.

Possible progression indicators include:

* increased tolerated load;
* increased tolerated volume;
* improved control under perturbation;
* improved symptom response;
* improved recovery after exposure;
* increased tolerance in relevant positions;
* reduced adverse response to normal training demands.

Pain tolerance alone is not progression.

---

## Recovery

Objective:

Improve readiness for future workloads and the ability to recover from training exposure.

Possible progression indicators include:

* improved subjective readiness;
* improved recovery time;
* improved tolerance of planned workload;
* reduced residual fatigue;
* improved sleep or downregulation response;
* improved low-intensity work tolerance;
* fewer required reductions in planned training.

Recovery training must not become an additional hidden stressor.

---

# Constraints

The Module Engine must always respect the following constraints.

---

## Power Constraint

Power must not be trained under significant neural fatigue or when maximal intent and movement quality cannot be maintained.

---

## Technical Quality Constraint

Technique has priority over load, volume and completion.

When technical degradation exceeds the acceptable threshold, the exercise or module must be modified or stopped.

---

## Recovery Constraint

Recovery capacity limits training volume, intensity, density and module count.

---

## Pain and Safety Constraint

Pain, medical restrictions and identified contraindications may:

* modify exercise selection;
* reduce training parameters;
* remove a module;
* require referral outside the engine's scope;
* block session generation.

The engine must not diagnose medical conditions.

---

## Primary Objective Constraint

Secondary modules must not compromise the session's primary adaptation.

---

## Time Constraint

The session must fit within the athlete's available duration.

The engine must reduce lower-priority content rather than compress all modules into unrealistic densities.

---

## Equipment Constraint

Only exercises compatible with available equipment and environment may be prescribed.

---

## Specific-Practice Constraint

Physical preparation must remain compatible with the quantity, intensity and timing of the athlete's specific-skill practice.

---

## Fatigue Constraint

No session exists to create fatigue.

Every session exists to create adaptation.

---

# Modification and Substitution

When a selected module cannot be implemented as originally planned, the engine must preserve the physiological objective whenever possible.

The engine should first attempt to modify:

* exercise;
* load;
* volume;
* intensity;
* range of motion;
* tempo;
* rest;
* density;
* complexity.

A module should be removed or postponed only when no valid implementation can preserve the intended adaptation safely.

Substitution decisions must preserve, as far as possible:

* primary adaptation;
* movement function;
* contraction characteristics;
* force or velocity intent;
* fatigue profile;
* equipment compatibility;
* athlete restrictions.

Detailed substitution rules are defined in the dedicated Substitution Rules specification.

---

# Validation

Every assembled session must pass validation before it is returned to the athlete.

Validation must verify that:

* every selected module is justified;
* every module has one primary adaptation;
* the session serves the declared objective;
* the order is coherent;
* the fatigue cost is acceptable;
* the duration is realistic;
* exercises are compatible with the selected modules;
* equipment requirements are satisfied;
* athlete restrictions are respected;
* progression rules are not violated;
* no blocking conflict remains unresolved;
* the output contains all required prescription data.

A session may produce:

* blocking errors;
* warnings;
* optimization recommendations.

A session containing a blocking error must not be presented as a valid training session.

Detailed validation rules are defined in the dedicated Validation Rules specification.

---

# Decision Trace

Every meaningful engine decision must be explainable.

The engine must be able to record:

* which modules were selected;
* why each module was selected;
* which modules were omitted;
* which constraints were applied;
* which conflicts were detected;
* how conflicts were resolved;
* which substitutions occurred;
* why the final module order was used;
* which warnings were generated;
* whether validation succeeded.

The Decision Trace must describe the actual decision process.

It must not generate a retrospective justification unrelated to the rules that were applied.

# Evolution

The Module Engine is designed to evolve.

New exercises may be added.

New sports may be supported.

New evidence may modify implementation.

New modules may be added when a distinct operational need is demonstrated.

New secondary adaptations may be documented when supported by identified evidence.

However, the core architecture remains stable:

Adaptation Domains define physiological objectives.

Capability Modules operationalize those objectives.

Training Cycles establish priorities over time.

Training Sessions assemble the required modules to execute those priorities.

Exercises implement the selected modules.

Repeated, validated training exposure produces long-term adaptation.

The engine must never reverse this sequence by allowing available exercises to define the athlete's physiological objectives.

---

# Definition of Success

The Module Engine succeeds when it consistently produces training structures that:

* target the required adaptations;
* respect athlete constraints;
* preserve technical quality;
* manage fatigue intelligently;
* remain compatible with specific practice;
* support measurable progression;
* minimize unnecessary work;
* remain explainable;
* remain reusable;
* remain testable.

The quality of the engine is measured by the athlete's safe and sustainable long-term progression.

It is never measured by:

* the number of exercises;
* the length of the session;
* the severity of fatigue;
* the complexity of the system;
* the novelty of the workout.

> The simplest valid structure that produces the required adaptation is the preferred structure.
